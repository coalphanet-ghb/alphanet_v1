## PHASE 0 — Data-correctness hotfixes (P0: we shipped a wrong number; smallest diffs, do first)

**0.1 Dedupe gate.** `s3_compute.validate_candidates` + `_series()`: enforce uniqueness on `(entity_id, metric_name, period_end)` — keep latest-sourced; series must never contain duplicate periods. Growth/CAGR functions assert distinct endpoints; identical-period or zero-denominator inputs → named insufficiency, never a value. (Root cause of the fake `revenue_yoy = 0.0%` that narrated 5 sections.)
**0.2 Compute self-audit.** Before emitting `computed_financials`: sanity pass (duplicate periods, single-point "series", growth from identical inputs) → suppress metric + insufficiency entry. The model detected our artifacts; we must detect them first.
**0.3 Layer rehydration.** When `s0` marks macro/sector fresh, `s2` must load that layer's stored evidence + extract pools from Supabase into `evidence_pool`. Freshness = "don't re-fetch," never "run without the data." (Root cause of the empty C section.)
**0.4 Pool version discipline.** On reuse, load only the **latest** `extract:{doc_id}` knowledge-entry version per document (multi-version pools caused the duplicate observations).
**Gate:** rerun SONA `--model M3`: no 0.0%-artifact, no duplicate EPS, C receives macro/sector evidence.

## PHASE 4 — Financial forensic architecture (the flagship: 3-statement deep-dive + concall cross-examination)

New graph: `s3 → [B, E, s4a_pl, s4b_bs, s4c_cf] → s4d_followup → s4e_fin_synthesis → F → G → H → C → I → J → s9 → s8`.
**4.1 s4a/b/c statement-forensic nodes** (new specs from ANALYST_KNOWLEDGE D1/D2/D3): each gets its `calc:*_table` + battery checks + statement-relevant evidence + guidance items. Dual job: statement analysis + **cross-examination protocol** — every management claim touching the statement tested against computed numbers → `claim_checks[]: {mgmt_claim, quote evidence_id, computed_ref, verdict: corroborated|contradicted|unverifiable, note}`.
**4.2 s4d_followup** (bounded 1 iteration, ≤3 LLM calls): statement nodes may emit ≤2 `followup_requests[]` each (`target: computed|evidence`); router answers computed ones in Python, evidence ones via keyword-filtered pool + one M3 call; answers appended as supplementary blocks.
**4.3 s4e_fin_synthesis** (rewrites `s4_financials` spec): integrated D — cross-statement triangulation verdicts, DuPont driver, quality-of-earnings, ratio analysis vs pack norms, **claims-vs-numbers scoreboard** (aggregate claim_checks). Contradicted claims auto-feed H and F.
**4.4 F moves after s4e** to consume the scoreboard in its credibility assessment. State adds `envelope_D1/D2/D3`, `claim_checks`, `followups`; D1–D3 persist as knowledge_entries; composer renders D from s4e.
**Gate:** D renders D1/D2/D3 + synthesis; scoreboard tests ≥5 management claims; ≥1 non-corroborated verdict handled and surfaced in F + H.
